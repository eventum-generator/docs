The Monitoring page is the dashboard for the whole application: every running instance added up, refreshed while the page is open.

With nothing running the live sections are replaced by a note pointing at [Instances](/docs/studio/instances).

## Pipeline

The three stages of generation as one line, with the totals since the instances started: timestamps **enqueued** by the input stage, events **produced** by the event plugins, and events **written** by the output plugins. Under the last two sit the losses that explain the difference — **dropped** and **failed** for the event stage, **write failed** and **format failed** for the output stage — in red once above zero.

Read left to right, the row answers where events are going missing without opening a single instance.

## Throughput

Input and output events per second over a moving window of roughly two and a half minutes, with the current rates named above the graph. The two lines together show whether the output stage is keeping up with the timestamps the input stage is producing.

## Failures

The same window for failures, with event-stage and output-stage failures as separate lines. The section appears only while something is failing, so an empty dashboard means there is nothing to report rather than a chart nobody needs to read.

## Instance load

Each instance's share of the total output rate, stacked over the same window, with a legend naming every instance, its current rate and its percentage of the total.

This is where an instance that is dominating the pipeline, or has quietly stopped contributing to it, becomes obvious.

## Resources

Four tiles for the machine and the process, each with its own recent history:

| Tile | Scope | What it reports |
|------|-------|-----------------|
| **CPU** | host | Current utilization, with core count and clock. |
| **Memory** | host | Used against total. |
| **Disk I/O** | app | Read and write rates, and the totals since start. |
| **Network** | app | Inbound and outbound rates, and the totals since start. |

Reading these next to the throughput graph separates a slow generator from a saturated machine: a plateau in output that lines up with a CPU ceiling is a different problem from one that does not.
